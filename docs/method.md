# 方法说明：中断风险、联系策略与督导口径

本文说明项目如何处理服务协议、计划到户时点、确认过的替代安排、联络授权、联络分派
和实际回单，以及为什么这样处理后才能回答站里的三个问题：

1. 哪些家庭真正可能失去约定照料；
2. 主动联系本身会怎样改变后来查到的结果；
3. 现有记录哪些能反映联络策略效果，哪些只能描述已联络个案。

## 1. 时点纪律

所有判断都带一个“预测时点” `as_of`（某个工作日，北京时间自然日）：

| 记录 | 可见规则 |
| --- | --- |
| 服务协议 `episodes` | 应约日在 `begins <= due < ends` 内才算原协议的应约 |
| 变更 `service_changes` | 只有 `recorded_on <= as_of` 才可见；可见后按 `starts`/`ends` 的实际期限生效，左闭右开 |
| 应约与回单 `checkpoints` | `due > as_of` 为“尚未到期”；`due <= as_of < received` 为“已到期、待回单” |
| 联络分派 `outreach` | `assigned_on` 不晚于应约日；`action_day` 为空表示未执行 |
| 联络授权 `permissions` | `withdrawn` 不可主动联系 |
| 回拨 `callback` | 已约定时间优先占用名额；`withdrawn` 不得当作新机会；`verified` 不重复占用 |
| 余量 `capacity` | 查证与改约各占一个名额，已承诺回拨另占一个查证名额 |

关键点：**变更从实际生效日起影响判断，而不是从登记日起**。例如 H064 的暂住
2026-06-07 生效、06-08 才登记；06-07 之后的应约已经暂停，06-08 之前做的预测则看不到
这条变更。家庭迁走或转出后，原协议终止，从终止日起不再承担“原协议中断风险”。

## 2. 三类家庭不能混在一起

对每个应约日，先判断它在 `as_of` 的协议状态（`service_risk.timeline.exposure_at`）：

| 状态 | 含义 | 是否计入中断风险 |
| --- | --- | --- |
| `at_risk` | 仍受原协议约束 | 是 |
| `suspended` | 与家人同住、暂住等已确认暂停 | 否，期间不承担原协议中断风险 |
| `covered` | 已确认由另一机构提供替代服务 | 否，由替代安排覆盖 |
| `ended` | 家庭迁走或转出，原协议终止 | 否，原协议风险结束 |

再判断结果能确认到什么程度（`classify_outcome`）：

| 结果 | 含义 | 进入二分标签 |
| --- | --- | --- |
| `not_due` | 未来还没到约定日期 | 否 |
| `awaiting_receipt` | 已到期、回单尚未收到 | 否 |
| `unconfirmed` | 回单已到、各渠道尚未查齐 | 否（既不算缺口也不算有服务） |
| `served` | 已证实有服务 | 是，`no_gap` |
| `covered_elsewhere` | 无原服务，但已有既有替代安排 | 是，`no_gap` |
| `gap` | 各渠道都证实无服务、且没有替代安排 | 是，`gap` |

“一个平台看不见回单”与“各渠道证实无服务”因此不会混为一谈。督导视图
（`service_risk.evaluation.exposure_report`）把到期已证实无服务、渠道未查齐、
尚未到期分别列出。

## 3. 风险经历（spell）

同一家庭可能反复开通、暂停、重新联系。`service_risk.timeline.spell_ids` 把连续、
仍受原协议约束的应约日划成一段经历，以下情况开新的一段：

* 应约日不处于风险中（暂停、替代覆盖、终止）；
* 换了一段协议（重新开通）；
* 应约间隔超过一周（中间没有约定服务）。

前向回测时，同一经历整段留在训练或整段进入复盘，避免把同一经历的前后混在一起。
例如 H064 的暂住把 `H064-1` 与 `H064-2` 之间切开；H106 迁走之后的应约不进入任何
风险经历。

## 4. 预测

`service_risk.risk` 用标准库实现一个带脊罚的 logistic 回归，特征只来自 `as_of` 时
已经收到回单、且当时处于风险中的更早应约日：

* 最近一次已确认结果（有服务 / 缺口 / 未查齐 / 由替代安排覆盖）；
* 连续有服务次数；
* 本协议内先前缺口次数与未查齐次数；
* 本协议已见回单数、是否参照了同家庭更早协议；
* 站点与分组。

训练样本不足 40 条时退回整体缺口率，并在每条预测上标注“低支持”。预测输出不会把
暂停、覆盖、终止的应约日算成风险，它们以 `state` 单独给出并注明原因。

“高风险”只表示优先核查，不表示已经发生缺口。

## 5. 联络会改变结果：三种证据身份

`service_risk.evaluation.assignment_evidence` 给每条联络分派一个证据身份：

| 识别 | 条件 | 能说明什么 |
| --- | --- | --- |
| `randomized_itt` | 登记分派、概率有效、执行日不早于回单日、观察窗成熟 | 可进入意向性队列；下一次结果查齐后才进入二分效果估计 |
| `descriptive_only` | 非登记分派（`discretionary`） | 只能描述已联络个案 |
| `not_usable` | 执行早于回单（结果被联系改变）、观察窗未成熟或协议已终止 | 不能用于评价联络效果 |

**执行日早于回单日**是最关键的一条：这次联系可能改变回单内容，因此该应约日不能
作为“未联系也会如此”的干净对照，也不进入训练。资料中共 63 条属于这种情况。

联络结果的含义按以下口径解释：

* `alt_confirmed`：主动联络后收到另一机构已接手的证明。改变的是**结果能否确认**
  （由无服务改记为有替代安排覆盖），不是证明避免了中断；
* `booked_new`：联络后新安排了服务，才可能真的避免中断；
* `no_change`：没有改变安排或证明。

## 6. 策略评估

`evaluate_strategy` 的主要估计量是“下一次约定服务是否出现已确认缺口”的意向性比较：

* 只用 `randomized_itt` 记录；
* 每个分派按其登记概率加权（Horvitz–Thompson）；
* 观察窗从应约日开始，到下一次约定服务为止；协议在此期间终止的，观察窗关闭；
* 差异方向为 `arrange - none`，区间按风险经历整段重抽样（自助法）。

在当前资料上可用的意向性记录很少（分派组内常常少于 10 条），区间很宽，只能给出
方向性参考。工具会显式写出这一点，而不是给出一个看似精确的效果数字。

`backtest_strata` 把前向回测按协议分组、站点、家庭同意的方式与最近一次状态拆开，
便于督导看“不同覆盖和联络策略下预警是否仍然找准服务缺口”。分组越小越容易过拟合，
因此每行都同时给出事件数与基线 Brier。

## 7. 每周联系计划

`service_risk.planning.build_weekly_plan` 按以下顺序排一周计划：

1. **已约定回拨先占名额**。`confirmed` 占用一个查证名额；`withdrawn` 作废，不能当新
   机会；`verified` 不重复占用。回拨登记站点与当前有处理权的站点不一致时，交给有权
   站点处理，避免重复联系。
2. **其余本周到期应约按风险排序**。仍在风险的个案才可能安排联系。
3. **授权与处理权检查**：`withdrawn` 不联系；已转出或由其他机构替代的家庭由承接
   机构处理，原站点不重复联系；迁走的家庭不安排原协议联系。
4. **直接改约（arrange）只送给对当前协议有处理权且本周有改约额度的站点**，并要求
   预测概率达到阈值、查证与改约名额都还有余量。其余只能查证（document），或因为
   名额不足/无资料列为 skip。
5. 每条计划都给出理由和**下周回到哪些事实**（下一应约日的回单核对）。

`reconcile_plan` 在下一周把计划对回事实，并把“下周能确认到什么程度”与“历史复盘
口径”分开写；未查齐的不会因为复盘时已确认而污染下周口径。

## 8. 督导视图

`service_risk.supervisor`：

* `weekly_briefing`：三个不同的名单——
  * **高风险与次高风险**：按当前可见记录预测概率较高的应约日，仍受原协议约束才列入；
  * **下一次联系可能改变安排**：本周计划中直接改约的个案；
  * **仅适合核查记录**：额度不足、未达改约阈值、授权撤回或没有处理权站点，只宜查证。
* `case_review`：按家庭查看预测、为什么给了这一种联系安排、最后确认了什么，以及
  每条联络证据能否用于评价这条安排。
* `strategy_review`：策略评估摘要，含证据身份计数与低支持限制。

低支持时（训练样本不足、可用意向性记录少于 40 条、某组少于 10 条、渠道未查齐比例
偏高），这些限制会在简报与个案里直接写出，而不是照常给出精确数字。

## 9. 命令

```sh
python3 -m service_risk predict 2026-07-01 --table
python3 -m service_risk plan 2026-07-06 --table
python3 -m service_risk briefing 2026-07-06 --table
python3 -m service_risk case H064 2026-07-06
python3 -m service_risk backtest 2026-02-23 2026-09-01
python3 -m service_risk strategy 2026-09-10
python3 -m service_risk exposure 2026-06-21 --horizon 28
```
